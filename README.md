# Aster 多账户交易管理与额度监控

新增 Linux 网页账户管理：多账户双向市价分批开仓，普通策略监控 **5x / 10x / 20x**，循环另按实际杠杆监控。每账户可设置最低开仓杠杆（**5x / 10x / 20x**，默认 **5x**）和风险约束上限（大于 0%、不超过 100%，默认 **50%**），暂停策略后在网页“策略设置”修改。BBO 价差不超过万 5。每仓占用保证金为 `|数量| × 标记价格 ÷ 实际杠杆`，全部仓位多空分别累加后除以 USD1 账户总权益，预测成交后的占用率不超过该账户设置。升杠杆后按新杠杆重算占用和额度并继续加仓，完成后汇总飞书通知。实盘凭据只放服务器环境变量。完整安装、配置和执行规则见 [Linux 交易部署说明](DEPLOYMENT.md)。

```bash
curl -fsSL https://raw.githubusercontent.com/hxx344/aster_5x/main/install-trading.sh | sudo bash
```

网页每个账户可使用**多空循环**：XAUUSD1、SPCXUSD1、CLUSD1 可任选，每账户一次只运行一个品种。杠杆自动沿用所选品种的实际持仓杠杆；空仓时沿用交易所当前设置，不再单独设置或修改循环杠杆。每轮先记录原始多空数量，再在剩余额度、保证金与价差满足时等量加仓；成交确认后开始计时，到时且价差再次达标才减回本轮新增量，核实原始数量和杠杆不变后进入下一轮。默认每边 1 万 USD1 深度价差 ≤ 0.1 bp、每边新增不超过 1 万 USD1、持仓 60 秒。保存不会启动交易；暂停且本轮完成后可切换品种。其他品种的普通加仓继续按各自条件运行，循环与迁移互斥。配置、计时及核对进度随升级保留。见 [多空循环说明](DEPLOYMENT.md#独立多空循环)。

有效的 **BBO / 深度 WS 更新可提前唤醒循环检查**。开仓调度先检查额度倍数，再用本地完整深度精确预筛；减仓直接检查深度，再由账户任务重新核对持仓、风险和发单前盘口；预筛只返回开仓或平仓机会，实际数量由账户任务重新计算。每账户合并相同条件的机会，优先派发至少间隔 1 秒，忙时只保留最新机会；余额、保证金、请求预算和异常退避继续生效，普通任务的到期时间不被推迟。没有有效 WS 信号时沿用原定时检查。

循环正常开仓和平仓从**行情触发到首次下单之间不查询 HTTP**：账户、保证金模式与必要的额度数据在后台更新，交易线程只读取热快照和本地有效盘口。私有账户推送收到变化就撤销旧快照，断线、过期或尚未预热时等待后台恢复；最终风控和订单落盘之后再次校验快照资格。`openOrders` 查询完全移除，历史成交补账也由后台处理。账户有效期从后台请求起点算起，最长 8 秒，不因读取而延长；启动检查及下单后的订单核对仍按各自流程执行。

本地重复计算按数据版本复用：循环成交更新与版本号在同一事务提交，滚动统计在新成交、迟到补账、窗口到期或时钟回拨时重新计算；账户日总量直接汇总各品种数据。同一版深度只排序和构建精确累计档位一次，每次使用仍核对时效与撤销状态。网页保留实时状态刷新，历史成交和成本按账本版本共享计算，只为当前账户传输变化的成交明细；切换账户立即刷新，退出登录清空本地历史缓存。

每日循环的保证金占用按**账户基础上限＋5 个百分点，最高 100%**检查，所有循环杠杆均适用。例如基础 90% 时，账户总占用最多 95%；循环可在该总上限内使用可用空间。其他品种、多空方向和已有持仓一起计入，不按批次重复增加额度。开仓前预留手续费与盘口成本，成交后再次核对；平仓和必要补救保持可执行。

循环支持每账户设置**成交量上限**（USD1，0 为不限），各品种分别使用此上限，各自限制 **UTC 自然日**和**滚动 24 小时**的成交量：只累计该品种的多空加仓、减仓和补救成交，不含手续费；每笔成交显示该品种当日累计量。切换品种保留各自历史与剩余额度，旧账本升级时按成交品种自动重建统计。开仓按两个窗口较小的剩余额度预留预计平仓量，额度不足时缩小下一轮或等待。UTC 00:00 只重置自然日统计，最近 24 小时成交仍计入额度，直到逐笔满 24 小时移出窗口；两个窗口及交易条件均满足后才自动恢复。手动暂停不会自动恢复；已有仓位的平仓和补救继续允许，实际价格变动可能使最终成交量超过预留。

当前所选品种的每日及近 24 小时同时显示**循环交易成本**：按指定 taker 费率 **0.0125%** 计算全部实际成交的手续费，加上同批等量买卖的实际成交差价。每笔明细拆分手续费、该笔计入的差价和总成本；有利差价可抵减成本。未配齐或仍在同步时标记成本未完整，历史已入账成交自动补算。此处为指定口径的成本统计，不含资金费或返佣。

循环卡片只显示简短状态，检查明细移到**执行记录**中默认折叠。同一账户、同一品种、同一开/平仓等待阶段的连续条件检查合并为一条，显示累计次数、首次与最近时间，展开查看最新实际值、要求值和检查时间；数值或失败条件变化也继续合并。中间出现交易、异常、启停或配置记录时另起一条。旧记录不删除，页面仅合并能明确识别的连续历史检查；普通加仓条件仍单独展示。

执行记录首位的**最近循环成交质量**按本批每边实际委托数量对照触发快照、发单前估计和原始双边成交价差，并显示本地 WS 接收→请求开始、最终深度检查→请求开始、请求开始→响应三段耗时；盘口、成交与响应明细默认折叠。完整价差只在两条原始订单均等量完全成交后确认；部分成交、未知结果和修复分别标明，修复成交不并入此价差。记录不新增交易所请求，耗时不代表交易所收到或撮合时间，也不保证实盘价差改善。

折叠明细中的“发单准备耗时”进一步拆分触发至账户任务开始、账户热数据读取、首轮规划与盘口、提交前账户复核、最终盘口与风控检查、订单记录写入及其他本地准备。账户读取和提交前复核只计量本地操作。它们解释 WS 接收至请求开始的总耗时；缺失的旧数据保持未知。

成交量循环与额度加仓可以在**同一账户按品种并行**：例如 XAU 循环运行时，SPCX、CL 仍按普通 5x / 10x / 20x 条件升档和加仓；只有 XAU 的普通加仓与普通升档被禁止，公共额度满足也不例外。下单前再次读取本账户保存的循环选择；其他账户的同品种不受限制。暂停账户或等待日/24 小时额度不会解除循环品种保护，关闭循环模式后解除。循环与仓位迁移仍互斥。

**普通加仓条件**始终可查看，分别展示 5x、10x、20x 额度、各档保证金上限及 BBO 价差的实际值和满足状态；缺失或过期数据不判定通过。循环所选品种单独显示普通加仓禁用原因，切换到其他品种可查看其普通执行状态。“启动账户 / 暂停账户”是账户总开关，同时控制两项功能；已有批次继续核对。两项功能共用账户风险额度，实际订单按批次依次提交与确认，不重复占用同一笔余额。

新版 `aster-desk` 的额度监控独立于盘口刷新，常规采样目标间隔 **2 秒**。账户与多空循环都启用、并取得所选标的实际杠杆后，仅该标的实际杠杆启用 **200 毫秒**采样调度；同标的多账户共用一次请求，其他档位保持常规更新。接口只接受标的参数、一次返回全部档位，程序只在高频轮次更新循环所用档位。同一标的始终只有一个请求在途，按两次请求开始时间计算间隔，慢请求不堆积。公共风控档位每 **60 秒**独立后台热更新，每次高频采样仅查询剩余额度；更新失败保留原数据与原时间，超过 **5 分钟**不可再用于额度判断。网页在当前杠杆下显示账户余量（账户上限减多空合计持仓），缺失或过期不显示可用数值。10x / 20x 额度满足已启用账户的网页阈值并通过持仓容量初筛，可用状态发生变化时，立即优先唤醒升杠杆及开仓路径，跳过普通账户轮次间隔；优先从 10x、20x 中选择可用的更高档，确认升档后立即尝试首批开仓。账户状态、额度、盘口和风控仍会重新检查，接口退避、预算及开仓冷却仍生效；请求耗时会增加延迟，不保证即时成交。

循环开仓先检查所选品种、实际杠杆的**公共剩余额度 ≥ 本轮多空合计目标名义价值 × 开仓额度倍数**，再检查热差价。目标取配置的名义价值上限：每边 10000 USD1、2 倍时，需要公共余量至少 40000 USD1；多空合计上限 10000、2 倍时需要 20000。倍数默认 1，可设 1–100，支持小数；旧账户自动使用 1 倍。仅使用请求开始起 1 秒内的对应杠杆额度，缺失、失败或过期时等待；额度更新可重新检查仍有效的热差价，发单前再次复核。账户档位余量、保证金、成交量限制与盘口检查继续生效。减仓及补救不检查公共额度，只处理本轮新增数量，核实回到原始多空数量后再开始下一轮。

新版同时支持**公共额度提醒**和**实盘交易完成汇总**，共用 `FEISHU_WEBHOOK_URL` 与可选的 `FEISHU_SIGN_SECRET`。已有机器人配置升级后直接沿用。公共提醒复用上述采样，不增加 Aster 查询，也不阻塞账户唤醒；阈值使用网页“策略设置”，多账户按关注该市场的最低阈值触发，暂停账户仍参与提醒，暂停策略不会因额度出现而自动启动。

公共提醒默认启用，可在 `/etc/aster-desk/environment` 设置 `ASTER_CAPACITY_ALERT_ENABLED=0` 单独关闭；冷却时间使用 `ASTER_CAPACITY_ALERT_COOLDOWN_SECONDS=300`，修改环境文件后执行 `sudo aster-desk restart`。旧 `ASTER_CAPACITY_ALERT_THRESHOLD` 不再覆盖网页阈值。每个组合首次达标提醒一次，持续高位不刷屏，回落后重新达标且冷却结束才再提醒。成功状态持久化，失败只在新额度仍有效且达标时重试；未配置 Webhook 时不积累公共提醒历史，演示模式不发送。交易汇总优先发送，HTTP 投递结果不确定时仍可能重复。提醒使用未扣个人占用的公开估算，完整说明见 [飞书、升级与运维](DEPLOYMENT.md#飞书升级与运维)。

升级保留新版环境文件和数据库，安装脚本会停用旧 `aster-5x` 服务以免重复轮询。新版不启动旧 `monitor.py`，也不自动导入旧 `alerts.json` 的提醒状态；首次启用时可能对当前达标额度提醒，之后重启沿用新的成功状态。

以下是保留的**旧版独立额度监控工具**说明，其安装命令、配置和历史迁移规则只适用于 `aster-5x`，与新版 `aster-desk` 分开管理。旧工具不会登录账户或下单，同时监控 **XAUUSD1、SPCXUSD1、CLUSD1**，每个标的按 **5x / 10x / 20x、每 5 秒检查、严格大于 10,000 USD1** 的规则独立触发。默认关闭飞书，触发只记入本地日志。纯监控无需第三方 Python 依赖。

九个“标的 + 杠杆”组合分别保存提醒状态和冷却时间；同一标的各档位共用一次接口快照，请求量不增加，一个组合的持续达标不会压制其他组合的提醒；普通网络失败只让对应标的退避，其他标的继续检查。遇到 429/418 限流则暂停新的查询请求，遵守服务端退避时间。

## 旧版独立监控：Linux 一键安装

在使用 systemd 的 Linux 服务器上执行（推荐 Ubuntu 22.04+、Debian 12+、RHEL 9+）：

```bash
curl -fsSL https://raw.githubusercontent.com/hxx344/aster_5x/main/install.sh | sudo bash
```

已经是 root 用户时去掉 `sudo`。服务器需要能访问 GitHub 和 Aster；若没有 `curl`，先运行 `sudo apt-get update && sudo apt-get install -y curl`（Ubuntu/Debian），或 `sudo dnf install -y curl`（RHEL 系列）。其余缺少的依赖由脚本安装，系统 Python 需至少 3.9。

首次安装按提示填写，全部回车即可采用默认值：

1. 阈值：`10000` USD1。
2. 检查间隔：`5` 秒。
3. 飞书 Webhook：可留空；填写后自动启用，再输入可选签名密钥。密钥输入不显示。

安装后服务立即启动、开机自动运行、异常退出自动重启。后续无需编辑 JSON：

```bash
sudo aster-5x status        # 当前额度、查询状态、阈值和飞书开关
sudo aster-5x configure     # 交互修改配置，保存后自动重启
sudo aster-5x logs          # 跟踪日志；Ctrl+C 只退出日志查看
sudo aster-5x test-feishu   # 手动发送一条标明“测试”的消息
sudo aster-5x stop          # 停止监控
sudo aster-5x start         # 恢复监控
sudo aster-5x restart       # 重启监控
```

配置时回车保留当前值；Webhook 输入 `-` 可关闭飞书并清除保存的地址与密钥。安装不会发送测试消息；启用飞书后，若第一次查询已达标，会发送正常额度提醒。

**升级：重新执行安装命令，配置与提醒历史会保留，默认监控三个标的的 5x / 10x / 20x。** 原有三个标的的 5x 提醒状态会自动迁移，新增档位单独建立提醒记录，阈值、间隔和飞书设置继续沿用。如果手动设置了 `symbols` 列表，则只监控该列表；支持上述三个代码。旧配置中的 `leverage: 5` 会自动升级为三个档位；如需手动限制档位，可设置 `leverages: [5]` 或 `[10, 20]`。配置列表中已移除的档位会自动过滤，过滤后没有受支持档位时恢复默认三档。服务与管理命令仍叫 `aster-5x`。无交互安装可用 `curl -fsSL https://raw.githubusercontent.com/hxx344/aster_5x/main/install.sh | sudo bash -s -- --non-interactive`，之后通过 `sudo aster-5x configure` 配置。已克隆仓库时也可执行 `sudo bash install.sh`，直接安装当前目录的代码。

程序位于 `/opt/aster-5x`，配置位于 `/etc/aster-5x/config.json`，状态和轮转日志位于 `/var/lib/aster-5x`。服务以独立 `aster-5x` 用户运行。`status` 分别显示九个组合的额度、检查时间和错误；只有所有组合数据新鲜且成功时才返回成功。部分成功显示 `partial`，不把单个成功当成全部正常。首次查询失败时安装命令会返回失败并显示原因，但已安装的服务仍会按退避规则重试；用 `logs` 排查。查看 systemd 原始状态：`sudo systemctl status aster-5x`。

## 数据口径

分别读取 `leverageOiRemainingMap` 中配置的 `5`、`10`、`20` 档位，各自取它与对应杠杆风控档位 `bracketNotionalCap` 的较小值。它是**不含个人持仓、挂单占用的公开可开额度**。网页会进一步扣除账户占用，因此公开额度达标不保证你的账户能开出同等仓位。程序不会登录账户、调整杠杆或下单。

2026-09-09 对照网页公开 JavaScript 核对了以下接口与计算方式，并完成无认证实测：

- `GET https://www.asterdex.com/bapi/futures/v1/public/future/common/symbol/leverageoi/remaining?symbol=XAUUSD1`
- `POST https://www.asterdex.com/bapi/futures/v1/friendly/future/common/brackets`，查询体 `{"symbol":"XAUUSD1"}`。
- 网页模块 `useTicker-iKEcy8XC.js` 和 `shared~...~e3kb53wr-C_GIamnV.js` 使用上述额度映射和风控档位，再扣个人占用。这些网页接口可能随站点变更；字段缺失或异常时程序报错，不把失败当作 0。
- [官方 API 文档](https://asterdex.github.io/aster-api-website/futures/account%26trades/#remaining-openable-notional-value-user_data)另有账户查询接口，本实现使用已核实的网页公开接口。

## Windows 运行与检查

需要 Python 3.9+，在 PowerShell 执行：

```powershell
cd D:\project_aster_5x
python -m unittest -v
python monitor.py --once
.\start.ps1
Get-Content .\runtime\status.json
Get-Content .\runtime\monitor.log -Tail 10
```

`--once` 会对所有配置标的各运行一次检查，若启用飞书且达标也会推送。后台监控已启动时不要同时运行它，单实例锁会阻止重复进程。`start.ps1` 以隐藏窗口启动；关掉终端不会停止它，但关机、休眠会中断监控。Windows 不自动设置开机启动。

停止：`python monitor.py --stop`。再次启动用 `start.ps1`。配置修改后需要停止并重启。`runtime/status.json` 的 `markets` 按 `交易代码:杠杆`（例如 `XAUUSD1:5`、`XAUUSD1:10`）保存检查时间、当前值与运行状态；顶层保存 PID、标的列表、`leverages` 列表、阈值和推送开关。只有对应标的 `status=ok` 且检查时间新鲜时才表示最新查询成功。错误状态保留上次成功值和时间，不能当成当前值。

5 秒为目标检查周期，网络请求、接口限流和重试会增加延迟，轮询之间的短暂波动可能漏过。失败指数退避，429 至少等 180 秒，418 至少等 24 小时。`Retry-After` 秒数更长时遵从服务端。

## 手动飞书配置（可选）

Linux 推荐使用 `sudo aster-5x configure`；手动配置时编辑 `/etc/aster-5x/config.json`。Windows 在已忽略的 `config.local.json` 中填写：

